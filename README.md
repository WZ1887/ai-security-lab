# AI Security Lab - RAG 与 Agent 安全攻防实战

本项目是一个面向 AI 安全（Security for AI）方向的实战演练库。基于本地大模型（Ollama + DeepSeek），针对 OWASP LLM Top 10 中的核心风险，构建了完整的攻击复现与防御验证。

## 🛠️ 技术栈
- 本地大模型：Ollama (DeepSeek-R1:1.5b)
- 向量数据库：ChromaDB
- 嵌入模型：nomic-embed-text
- 开发语言：Python 3.13

## 🚨 已复现的安全风险与防御方案

### 实验一：提示词注入与越狱（OWASP LLM01）
- **攻击场景**：直接注入（伪装权威）、角色扮演绕过（导致模型退化性循环/DoS）。
- **核心文件**：`01_prompt_injection/`

### 实验二：Agent 工具滥用与越权防御（OWASP LLM06）
- **攻击场景**：攻击者伪装管理员，诱导模型输出 `RESET_PASSWORD|admin|hacked` 的越权工具调用指令。
- **防御方案（零信任）**：在 Python 后端工具执行层引入强制鉴权，无视 AI 输出逻辑，只校验当前真实会话身份。
- **核心文件**：`02_agent_security/`

### 实验三：RAG 投毒攻击与数据清洗（OWASP LLM02/01）
- **攻击场景**：在本地知识库上传包含“系统指令”的毒文档，大模型在 RAG 检索时被投毒文档劫持。
- **防御方案（硬防御）**：在 `build_db.py` 入库阶段引入数据清洗机制，通过恶意特征词过滤，在数据进入向量数据库前将其物理丢弃。
- **核心文件**：`03_rag_security/`

### 实验四：多 Agent 信任链攻击与零信任防御（OWASP LLM06）
- **攻击场景**：基于微服务架构模拟“客服 Agent”与“财务 Agent”的通信。攻击者通过提示注入洗脑客服 Agent，使其向财务 Agent 传递越权转账指令。
- **防御方案（执行层鉴权）**：前端大脑被欺骗，但在最终执行工具（`execute_transfer`）时，后端代码强制校验会话身份，成功阻断越权转账。
- **核心文件**：`04_multi_agent/`
### 实验五：数据脱敏与隐私保护（OWASP LLM02）
- **攻击场景**：用户输入包含手机号、邮箱等 PII 敏感信息，直接发给大模型极易造成隐私泄露。
- **防御方案（代码层脱敏）**：在 Prompt 发送给 AI 之前，利用正则表达式替换敏感信息（如 `<PHONE_0>`），待 AI 返回结果后，在展示层还原真实信息，满足 GDPR 与《个人信息保护法》要求。
- **核心文件**：`05_privacy_security/`

### 实验六：API 资源耗尽攻击与防御（OWASP LLM10）
- **攻击场景**：API 未设限时，攻击者可发送 100KB 的“Token 炸弹”撑爆上下文窗口，或发起高并发 CC 攻击耗尽后端资源，导致服务瘫痪（DoS）。
- **防御方案**：
  1. **输入长度限制**：使用 Pydantic 校验器，在网关层直接拒绝超长输入（Token 炸弹拦截成功率 100%）。
  2. **原生限流器**：在代码层基于 IP 记录请求时间戳，限制 5次/分钟，阻断 CC 攻击（成功拦截并返回 429 状态码，保护 Ollama 免于崩溃）。
- **核心文件**：`06_api_security/`

### 实验七：微服务架构对抗综合演练
- **实验架构**：完全解耦的微服务架构（数据库、API网关、客服Agent、财务Agent、攻击者Runner独立运行，通过标准输入/输出通信，模拟真实 HTTP API 调用）。
- **攻击链验证**：验证了“直接注入”在网关被拦；“RAG 数据越权”因为数据隔离，大模型根本看不到别人的数据；正常业务请求则正常返回，并完成了 PII 脱敏还原。
- **工程规范**：严格执行“日志归 stderr，业务数据归 stdout”的工业标准，规避了微服务间数据解析失败的问题。
- **核心文件**：`07_full_system_simulation/`

### 自动化扫描实录（Garak实战）
- **实验过程**：引入 NVIDIA Garak 对本地模型进行自动化 Prompt Injection 扫描。
- **发现风险**：在 CPU 推理环境下，Garak 高强度的并发探测直接导致本地 Ollama 服务崩溃（ConnectionError）。这印证了资源耗尽（DoS）是 AI 服务最致命的底层风险之一。安全防御不仅需要应用层代码保护，还必须有 API 限流、超时机制以及硬件资源的冗余扩容。
