### 实验五：数据脱敏与隐私保护（OWASP LLM02）
- **攻击场景**：用户输入包含手机号、邮箱等 PII 敏感信息，直接发给大模型极易造成隐私泄露。
- **防御方案（代码层脱敏）**：在 Prompt 发送给 AI 之前，利用正则表达式替换敏感信息（如 `<PHONE_0>`），待 AI 返回结果后，在展示层还原真实信息，满足 GDPR 与《个人信息保护法》要求。
- **核心文件**：`05_privacy_security/`

### 实验六：API 资源耗尽攻击与防御（OWASP LLM10）
- **攻击场景**：API 未设限时，攻击者可发送 100KB 的“Token 炸弹”撑爆上下文窗口，或发起高并发 CC 攻击耗尽后端资源，导致服务瘫痪（DoS）。
- **防御方案**：
  1. **输入长度限制**：使用 Pydantic 校验器，在网关层直接拒绝超长输入（Token 炸弹拦截成功率 100%）。
  2. **原生限流器**：在代码层基于 IP 记录请求时间戳，限制 5次/分钟，阻断 CC 攻击（成功拦截并返回 429 状态码，保护 Ollama 免于崩溃）。
- **核心文件**：`06_api_security/`

### 实验七：微服务架构对抗综合演练
- **实验架构**：完全解耦的微服务架构（数据库、API网关、客服Agent、财务Agent、攻击者Runner独立运行，通过标准输入/输出通信，模拟真实 HTTP API 调用）。
- **攻击链验证**：验证了“直接注入”在网关被拦；“RAG 数据越权”因为数据隔离，大模型根本看不到别人的数据；正常业务请求则正常返回，并完成了 PII 脱敏还原。
- **工程规范**：严格执行“日志归 stderr，业务数据归 stdout”的工业标准，规避了微服务间数据解析失败的问题。
- **核心文件**：`07_full_system_simulation/`

### 自动化扫描实录（Garak实战）
- **实验过程**：引入 NVIDIA Garak 对本地模型进行自动化 Prompt Injection 扫描。
- **发现风险**：在 CPU 推理环境下，Garak 高强度的并发探测直接导致本地 Ollama 服务崩溃（ConnectionError）。这印证了资源耗尽（DoS）是 AI 服务最致命的底层风险之一。安全防御不仅需要应用层代码保护，还必须有 API 限流、超时机制以及硬件资源的冗余扩容。
